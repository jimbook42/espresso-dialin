# Espresso Dial-In v4.15.4 historical transfer hotfix

Transfer & Backup preserves older Espresso Dial-In records and their stored values. The updated Android app restores both the original v1 archives and v2 archives that contain richer data such as typed views or shared references.

Update Android to v4.15.4 before importing a v2 archive. Keep the original PWA and backup file, then review the import preview and run Verify imported data after restore. Bluetooth pairing and camera permissions remain local to Android.

## Technical notes

- The main Dexie schema is unchanged. Compatibility tests open schemas 1, 6, 10, 11 and 17 in temporary databases and compare the stored data after restore and re-export. See [the historical audit](HISTORICAL-TRANSFER.md).
- Transfer diagnostics identify a dataset, record position, field position or archive part. Positions are zero-based. Field positions follow sorted field names, which the error does not display. Unexpected browser or storage errors are shown as generic messages.
- Before promotion, verify the staged production deployment, exact source SHA, and both current alias mappings. The rollback target is the existing v4.15.3 deployment, dpl_E72KF6h6DfTwbk2aVCkhnzCivuio. If rollback is authorized, restore that deployment and inspect both aliases individually. Keep the v4.15.4 Android APK available for any v2 backups already exported.
- Test the installed PWA and native Android file picker on the actual device before relying on the transfer for real data.
