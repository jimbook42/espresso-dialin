# v4.15.3 release preparation

User-facing release notes:
- Back up the whole app locally, including history, settings and the latest saved replay.
- Import the backup on Android, review the replacement and verify the restored records.
- A recovery copy protects the previous Android data if a transfer is interrupted.
- Pair Bluetooth scales again and grant camera access on Android.

Release procedure, only after Isaac approves deployment:
1. Inspect Vercel team jimbook, project espresso-dialin and both current alias targets. Record the deployment IDs and confirm their v4.15.2 provenance before changing anything.
2. From a clean checkout of the approved commit, use the authenticated Vercel CLI to stage a production deployment without assigning domains (`vercel deploy --prod --skip-domain`). Do not use a Git-triggered deployment. Ensure the production build uses camera and scale enabled and simulation/replay disabled, and passes release preflight with the exact full source SHA. If deployment metadata cannot establish the exact SHA, stop and resolve provenance first.
3. Inspect the staged deployment and build logs. Verify version, SHA, flags, backup export and regression checks on the staged URL using disposable data. Preserve the existing alias targets for rollback. Obtain approval for the actual alias change if the existing approval does not cover it.
4. Promote the tested production deployment and inspect both espresso-dialin-puce.vercel.app and dialin-app.vercel.app individually. Confirm each target, version and SHA. Verify the original origin serves the exporter without clearing browser storage. If either alias remains elsewhere, stop and resolve it with explicit authorization before claiming release success.
5. Keep the source PWA installed. Follow FULL-APP-TRANSFER.md for export, Android import, verification and device testing. Do not uninstall or clear Android data.

Technical record: the final Git commit identifies this preparation. Record the exact SHA, CI/test results, APK SHA-256, debug certificate fingerprint and actual alias targets in the release ticket after verification. Physical Android file picker, force-stop persistence, camera and scale remain unverified.
