# v4.15.5 Galaxy S23 Ultra beta acceptance

This checklist covers the local debug update for package `com.jimbook.espressodialin`, version 4.15.5, version code 4.

## Install over v4.15.4

1. In the native v4.15.4 app, note the shot and bean counts, key settings and a familiar older shot. Keep a verified full-app backup.
2. Copy `espresso-dial-in-v4.15.5-debug.apk` to the phone's Downloads folder over USB in File transfer mode. In **My Files → Downloads**, open the APK and accept the update. If prompted for install permission, grant it to My Files for this install and turn it off afterward. If Samsung Auto Blocker blocks the APK, use Samsung's instructions for a temporary exception and re-enable it afterward. [Samsung installation guidance](https://www.samsung.com/us/support/troubleshoot/TSG10001914/)
3. If the installer rejects the update or asks you to remove the installed app, stop and record its message. Keep v4.15.4 and its data in place.
4. Open the native app. Confirm version 4.15.5 and compare History, Beans, Stats and settings against your baseline, including the older shot. Check the original installed Chrome PWA separately and confirm its history and settings are still present.

## Test diagnostics, contributions and SEP

- [ ] From **Settings → Report a problem**, open the preview without choosing a shot. Check app version, full Git SHA and recent events. Leave optional attachments off. Check that device model, device addresses, private notes, shot samples and media are absent by default.
- [ ] Check that sharing and saving require consent. Cancel the Android share sheet, reopen the report and confirm it and the saved history remain available. Choose Gmail on the next attempt, confirm the JSON is attached, send to the intended recipient and verify the recipient can open it. An opened chooser or draft confirms only that step.
- [ ] Use **Save file**, select Downloads and open the saved JSON from My Files. Force-stop Espresso Dial-In from Android App info, relaunch, and verify the new report still shows events from before the force-stop.
- [ ] In **History → Shot profile → Share Shot → Contribute shot data**, preview one shot. From **Settings → Contribute shot data**, preview multiple selected shots, then all eligible shots. Review counts, consent and omission of private notes, raw IDs, addresses and media. Share a reviewed JSON and confirm receipt. Validate the received copy with `node scripts/validate-beta-contribution.mjs path/to/file.json`. If the all-shots selection exceeds the 8 MiB limit, verify the size message and repeat with smaller selections.
- [ ] For a saved shot with eligible sensor data, use **Share to compatible app (SEP CSV)**. Confirm the recipient can open the file. If the receiver supports import, compare its timestamps and pressure/weight traces against the original recording. Record chooser, receipt and import outcomes separately.

## Report a failure

Record the checklist item, app version and SHA, Android/One UI version, exact steps, expected result, observed result and any visible error. If useful, use **Report a problem** or attach the locally saved JSON after reviewing it. If the update or launch fails before a report is available, record the installer or launch message. Stop if existing data appears missing and keep the backup and installed app available for investigation.
