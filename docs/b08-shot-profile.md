# B08 shot profile

The v4.14.16 History cards already showed saved dose, yield, duration and taste. Standalone Pressure Tracker also showed its saved brew ratio. History used `ShotPressureChart` for pressure-only shots and `ScaleFlowChart` for scale shots. Dial shots could overlay measured pressure or a recipe curve on the flow plot. Standalone shots drew separate charts. Both charts used responsive SVG. Stats aggregated recent shots and remains separate from the individual profile.

`ScaleFlowChart` now supplies the axes, paths and gap markers in the expandable History profile for all experiences. It reuses the pressure display filter also used by `ShotPressureChart`. The profile only draws measured pressure and observed scale weight, plus flow derived from the weight curve. The Weight view is the recorded scale load in grams. The app cannot recover beverage-only mass from an old untared curve. Saved yield and last observed scale weight are separate because yield may be entered by hand or resolved during settlement.

Average flow divides net change by the total duration of contiguous observed intervals. Peak flow uses the existing plot smoothing restarted after each gap. With a saved extraction window, both metrics and the flow plot use complete intervals inside that window. The weight plot keeps recorded settlement samples. Historical records may include the settlement tail in their flow because its start was never stored. Pressure peak comes from the raw valid readings. The plot uses display smoothing and shows gaps. The cursor gives the last observation within an uninterrupted run and lists the observation time for each value.

## Timeline

The app starts its timer on a monotonic clock and records a browser wall-clock origin at the same time. Pressure records time from the reader's own session start using the timestamp of the accepted observation. Scale notifications are timestamped on receipt, relative to the scale recorder's extraction start. That recorder can begin just before the app timer when there is no pre-infusion. With pre-infusion, it starts when the app advances to extraction. The browser clock can place the observations on a shared axis. Camera and Bluetooth latency prevent an exact measurement of physical simultaneity.

Manual extraction end is the stop event. For automatic stops, the detector's selected extraction end can precede confirmation and timer stop. The pressure capture can continue until confirmation. Scale capture can continue through yield settlement. Neither the rounded saved duration nor the last sample identifies the point at which extraction ended.

New sensor recordings carry the optional `shotProfileTiming` object. Its `version: 1` offsets are in milliseconds relative to the app timer's browser wall-clock origin. The fields are `pressureOriginMs`, `scaleOriginMs`, `extractionStartMs`, `extractionEndMs`, `stopMs` and `settlementEndMs`. A null value represents unavailable evidence. `clockDriftMs` compares wall-clock and monotonic elapsed time at stop. Differences above 250 ms disable cross-sensor inspection. `scaleInterrupted` records a disconnect observed after scale capture began. `yieldSource` describes entered or scale-filled yield where known, including when the scale fallback had no recorded observation.

The app copies the scalar timing evidence from the existing B06/B07 lifecycle trace at save time. Previously it was available only in memory. The saved object carries no diagnostics payload, raw observations, device identity or extra wall-clock timestamps. Existing rows, CSV fields and Diagnostics v2 exports retain their existing formats.

Older Dial pressure retains the 0.35-second display lead, including the clamp at zero. Old scale charts retain the estimate from the app's historical `Pre-infusion: Ns.` notes prefix. That prefix only affects legacy placement. The profile labels these estimates and disables a cross-sensor cursor when timing is uncertain.
