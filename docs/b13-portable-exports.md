# B13-A portable shot exports

Open **History → Shot profile → Share Shot** for the shot JSON, summary CSV and eligible SEP CSV. **Preferences & Settings** has the all-shots JSON download and restore preview. Downloads and restores work offline. The all-shots JSON covers recorded shots and their linked beans, including favourites, bean references and saved taste ratings. Active recipes, global preferences and separate replay files are outside the shot backup. A saved gauge JPEG is part of its shot record.

## Portable JSON v1

The envelope identifies the format as `espresso-dial-in/shots`. Each `record` retains the saved shot fields, including the original timestamp string and the sensor arrays in their original clocks. `measurements` makes unavailable values explicit with `null`, including legacy yield placeholders marked `unobserved-scale`. The raw record retains those stored fields for round-trip recovery. The two sensor descriptions give the saved source and clock origin where known and indicate whether extraction alignment passed the existing recorded-clock checks. Their observed indices and gap indices refer to the raw arrays. Entries with missing values stay in those arrays. The flow intervals are unsmoothed changes in observed scale weight per second in the scale clock, interrupted at missing readings, resets and gaps. The format carries no inferred input-water measurement. Missing provenance stays unknown.

Restore requires UTF-8 JSON up to 64 MiB, with a supported envelope, unique IDs, valid shot timestamps and consistent selections. The preview shows what can be added. Confirming runs a single IndexedDB transaction and rechecks the preview against current storage. Matching shots are skipped, conflicting IDs keep the local records and conflicting shots contribute no new selections. A vacant bean reference can be restored for a new or identical eligible shot. Existing bean records and reference choices take priority. Restore preserves historic linked bean names, including whitespace-only names. A historical shot whose bean is absent can still be recovered, and the preview counts such shots. Conflicting records remain available in the input file. For a collection exceeding the size limit, download individual shot backups from Shot Profile.

Blank bean age and storage cells in CSV represent missing values. The CSV importer preserves those blanks as missing, and retains explicitly exported age zero and bag storage. The shot-summary CSV rounds a calculated ratio to one decimal and preserves any saved ratio.

## SEP and Visualizer file format

The SEP-compatible CSV structure is taken from actual Smart Espresso Profiler and Coffee Flow exports in the Visualizer parser tests. The file starts with the unquoted `information_type` header. It uses `meta` rows and distinct `moment` rows with `sample: pressure` and `sample: weight` comments. The fixture excerpt in this repository comes from the Profitec/Coffee Flow example. [Visualizer SEP parser](https://github.com/miharekar/visualizer/blob/8e33c0ce3fe3856a6cfb0c48008e831b8edf7da0/app/models/parsers/sep_csv.rb) · [Parser tests](https://github.com/miharekar/visualizer/blob/8e33c0ce3fe3856a6cfb0c48008e831b8edf7da0/test/models/parsers/sep_csv_test.rb) · [Known-good Profitec CSV](https://github.com/miharekar/visualizer/blob/8e33c0ce3fe3856a6cfb0c48008e831b8edf7da0/test/files/profitec_victoria_arduino.csv)

Eligible exports use saved observations with physical sensor provenance. When both clocks are present, elapsed times share the earliest recorded origin or extraction start. A lone physical stream can use its recorded local clock. The Date metadata is the saved shot date. The adapter leaves the flow and temperature columns empty and writes no synthetic gap rows. Visualizer may resample the series and calculate flow from weight after import. Portable JSON retains the original gap markers and values. A shot with ambiguous paired timing, repeated timestamps within a stream, or an unsupported parser grid has no SEP download. Android and iOS SEP import still need device checks.

## Beanconqueror

The converter produces the v1 `ADD_BREW` envelope or the all-or-nothing `ADD_BREWS` batch envelope of up to 50. Eligibility requires a compatible saved ISO timestamp, explicit water input in mL, explicit beverage output in g, brew time in seconds and a saved preparation method. Pressure Tracker records lack water input and can also lack beverage output. The current Dial recorder also lacks water input. The converter preserves valid zeros and declines unavailable fields. Installed-app acceptance of gzip/base64url, numbered `shareBrew` parameters and the resulting links requires a real-device check. [Beanconqueror contract and examples](https://github.com/graphefruit/Beanconqueror/blob/d766c6f356516ca74386a92d64c7178f87785bbb/docs/brew-import-api.md)

## Future authorised Visualizer integration

Use the SEP file as multipart `file` in `POST https://visualizer.coffee/api/shots/upload`. The documented limit is 10 MB and content detection checks the leading `information_type`. The conversion and multipart field are tested locally against the published format. [Visualizer API](https://apidocs.visualizer.coffee/) · [OpenAPI upload contract](https://github.com/miharekar/visualizer/blob/8e33c0ce3fe3856a6cfb0c48008e831b8edf7da0/openapi.yaml)

For an authorised follow-up, register the public client as non-confidential. Use authorization code with S256 PKCE, a verified per-request state and a registered redirect URI. Exchange the code with its verifier, request only the `upload` scope and send the access token in the Bearer authorization header. Keep credentials and refresh tokens out of shot files and logs. Use a per-account mapping from local shot ID and export fingerprint to the server's returned `id` UUID, and coalesce simultaneous submissions. After an uncertain result, retry the same bytes so telemetry-based deduplication can resolve the retry. The API can update an existing matching shot and returns its existing UUID. An upload-only client can retain that UUID without requesting read or write scope. OAuth registration, credential storage and authenticated upload are deferred.
